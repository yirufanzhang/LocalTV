## 1. 一句话

LocalTV 是跑在用户自己电脑上的创作台：打开本地页面，选模型、把 Seedream 与 Seedance 的参数配全，再用自己的火山方舟 API Key 生成图片和视频，成片和任务记录留在本地项目里。

生成计算在火山方舟云端完成。本地负责理解需求、选择模型、提交任务、轮询、下载和保管素材。第一期不在本机加载模型权重。

## 2. 为什么做

LibTV（Liblib.tv）已经证明了一条顺手的用法：人对 Agent 说一句话，Agent 去生图、生视频，再把结果取回来。它的智能编排和模型路由在 LibTV 云端，本地 Skill 主要是上传、传话、轮询、下载。计费和密钥也挂在 LibTV 账号上。

LocalTV 要的是同一类体验，但控制权留在用户侧：

- 密钥是用户自己的火山方舟 API Key，费用走用户自己的方舟账户。
- 提示词、参考图、成片和任务状态默认只存在本机项目目录。
- 选哪个 Seedream / Seedance 模型、什么分辨率和时长，由本地策略决定，并可被用户覆盖。
- 不经过另一家创作平台做二次转发。

因此 LocalTV 不是 LibTV 的私有化复刻，也不是方舟控制台的换皮。它是一层本地创作代理：对人隐藏 API 细节，对模型保持直接调用。

## 3. 产品定位

| | LibTV | LocalTV 第一期 |
| --- | --- | --- |
| 运行位置 | 创作智能在云端，本地只做搬运 | 意图理解、任务编排、素材管理在本机 |
| 账号 | LibTV Access Key | 用户自己的火山方舟 API Key |
| 模型 | 平台聚合多家模型 | 只接 Seedream（图）和 Seedance（视频） |
| 结果 | 云端会话 + 可下载到本地 | 以本地项目目录为唯一事实来源 |
| 交互 | 自然语言会话 | 本地页面配全参数；命令行和 Skill 共用同一套参数 |

第一期服务三种人：

1. **自己做图和短视频的创作者。** 希望一句描述就出图、出片，文件留在自己电脑上。
2. **在 Cursor 等环境里工作的开发者。** 希望宿主 Agent 能调用 LocalTV，把「给这个角色出一张定妆图」「按这张图改背景」「用这段描述出一条 5 秒视频」变成可重复的本地任务。
3. **需要可控成本的个人或小团队。** 自己充值方舟，自己看每次调用用了哪个模型和哪些参数。

## 4. 产品原则

1. **本地优先。** 项目、输入、输出、任务日志都在本机。没有 LocalTV 自己的账号体系。
2. **密钥只属于用户。** Key 不进项目目录、不进 git、不写进日志。调用失败时也不回显完整 Key。
3. **直接调用模型。** 第一期只对接火山方舟官方 API，不包一层第三方聚合。
4. **参数在页面上配全。** 方舟公开的请求参数都出现在创作页上。当前模型不支持的项禁用并说明原因，不偷偷丢掉用户改过的值。
5. **默认能用，改动才提交。** 打开页面即可生成。没动过的参数沿用该模型的官方默认值，不额外传字段；用户改过的参数原样提交。
6. **一次任务一条记录。** 每次生成都能回溯提示词、模型、页面上的全部参数、输入文件、远程任务 ID 和本地输出路径。
7. **失败说人话。** 鉴权失败、审核拦截、参数不合法、额度或并发打满，要告诉用户下一步改什么，而不是只抛原始报错。
8. **不绕过平台审核。** 方舟拒绝的内容，LocalTV 原样停止并说明原因，不提供规避审核的能力。

## 5. 第一期做什么

第一期以文生图、图生图、文生视频为主路径，并在同一页上配齐这两个系列的公开参数。

| 能力 | 优先级 | 模型系列 | 用户给出 | 用户得到 |
| --- | --- | --- | --- | --- |
| 文生图 | P0 | Seedream | 文字描述 | 一张本地图片 |
| 图生图 | P0 | Seedream | 本地参考图 + 编辑说明 | 一张本地图片 |
| 文生视频 | P0 | Seedance | 文字描述 | 一条本地视频 |

人通过本地创作页完成这三条能力。页面上的参数按第 7 节铺全，不按「常用三项」裁剪。命令行和 Agent Skill 提交同一份参数，不另做一套更少的字段。

为了让这些参数真能选、真能生效，页面同时带上参数所依赖的输入方式：多张参考图、组图、图层拆分、透明通道、首帧、首尾帧、全模态参考、视频编辑、视频延长、样片。这些都走现有的图片或视频接口，不另接供应商。

### 5.1 明确不做

- 短剧分镜编排、音乐生成 MV、本地 ffmpeg 剪辑。
- 除火山方舟以外的供应商。
- 本机推理、模型权重下载、离线生成。
- 多用户、团队空间、云端同步、LocalTV 自己的计费。
- 在画布上圈选局部重绘。继续改图时，把上一张结果再放进参考图。

## 6. 用户怎么用

主入口是本机浏览器里的创作页，地址只监听本机（默认 `http://127.0.0.1` 上的一个端口）。命令行和 Skill 调用同一套参数校验，不提供比页面更少的字段。

### 6.1 首次配置

用户在火山方舟创建 API Key，并确认账号已开通所用的 Seedream、Seedance 模型。然后在创作页的设置里填入 Key，或在终端执行：

```bash
localtv config set-key
```

Key 写入用户主目录下的配置文件，页面和终端都不回显全文。未配置 Key 时，生成按钮不可用，并说明要去哪里创建 Key、本地配置写在哪个文件。

### 6.2 在页面上生成

创作页分成四块，参数面板一直展开，不收进二级弹窗：

1. **模式。** 先选图片或视频，再选具体任务。图片：文生图、图生图、组图、图层拆分。视频：文生视频、首帧、首尾帧、全模态参考、编辑视频、延长视频、用样片出正式片。当前模型不支持的任务置灰，并写明要换哪一档模型。
2. **提示词和素材。** 提示词始终可见。选了需要素材的任务后，出现对应的图片、视频、音频槽位，并显示还能再加几张。本地文件由程序编码后提交，用户不必先上传到对象存储。
3. **参数。** 右侧列出第 7 节的全部参数。常用项在上，进阶项在下，两组都直接可见。每一项显示官方字段名、当前值、该模型的可选范围。不支持的项保持可见但禁用，避免用户以为产品漏了这个开关。
4. **结果。** 提交前先给出本次真正会发给方舟的字段摘要。图片返回后直接预览；视频显示排队、生成中、成功、失败或超时，成功后播放本地文件。同一组参数可以存成预设，也可以再跑一次。

换模型时，已经选出但新模型不接受的值退回该模型的官方默认，并在参数旁提示改过了什么。互斥项不能同时打开，例如图片的「分辨率档位」和「自定义宽高」、视频的「时长」和「帧数」、JPEG 和透明通道、首帧 / 首尾帧 / 全模态参考。

### 6.3 宿主 Agent

Cursor 或其他支持 Skill 的 Agent 不直接拼方舟请求。它调用 LocalTV，传入与页面相同的参数结构，再把本地文件路径交回给用户。Agent 没提到的参数沿用官方默认，不擅自改成另一套「简化参数」。

## 7. 功能需求

### 7.1 配置

- 保存、替换、删除方舟 API Key。
- 可改 API 基地址，默认 `https://ark.cn-beijing.volces.com/api/v3`。
- 可改默认图片模型、默认视频模型。
- 可查看当前配置，但 Key 只显示末尾四位。
- 支持环境变量覆盖配置文件，便于临时切换账号。环境变量存在时优先于文件。

建议的环境变量名：`ARK_API_KEY`。配置文件默认位置：`~/.localtv/config.toml`，文件权限仅当前用户可读写。

### 7.2 项目与素材

一个项目是一个本地目录，默认在用户指定的工作区下，例如：

```text
项目目录/
  project.json          # 名称、创建时间、默认模型
  inputs/               # 用户放入或程序复制的参考图
  outputs/              # 生成的图片和视频
  jobs/                 # 每条任务一条 JSON 记录
```

第一期的「当前项目」可以就是用户正在使用的目录。不强制云端项目 ID，也不做账号级项目列表。多项目就是多个目录。

任务记录保存页面上的完整参数，而不只是提示词和模型：本地任务 ID、任务类型、状态、模型 ID、提示词、实际提交给方舟的字段、输入文件、输出文件、方舟任务 ID、创建与结束时间、错误摘要。

参数预设单独存在本机，一条预设等于一次创作页的完整选择，可以套用到新任务上。

### 7.3 页面上的图片参数

图片页对应 `POST /images/generations`。下面每一行都是页面上的一个控件。模型不支持时控件仍在，处于禁用状态，旁边写支持它的模型。

| 页面项 | 方舟字段 | 可选值与默认 | 哪些模型能用 |
| --- | --- | --- | --- |
| 模型 | `model` | 第 8 节列表；进阶可改填 Endpoint ID | 全部 |
| 提示词 | `prompt` | 文本。建议中文 300 字、英文 600 词以内，超出只提示、不截断 | 全部。5.5 / 5.0 pro / flash 另支持多语种 |
| 参考图 | `image` | 本地文件，可多张。5.5 / 5.0 pro / flash 最多 10 张；5.0 lite / 4.5 / 4.0 最多 14 张 | 图生图、组图时使用 |
| 尺寸方式 | `size` | 三选一：只选档位；档位加比例；自定义宽高。后两种提交 `宽x高` | 全部，档位不同 |
| 分辨率档位 | `size` | 5.5 / 5.0 pro / flash：`1K`、`1.5K`、`2K`，默认 `2K`。5.0 lite：`2K`、`3K`、`4K`。4.5：`2K`、`4K`。4.0：`1K`、`2K`、`4K` | 按模型切换选项 |
| 比例 | `size` | `1:1`、`4:3`、`3:4`、`16:9`、`9:16`、`3:2`、`2:3`、`21:9`。选中后按该模型文档里的像素表换成 `宽x高` | 与「只选档位」互斥 |
| 自定义宽高 | `size` | 两个数字。5.5 / 5.0 pro / flash：总像素 921600–4624220。5.0 lite / 4.5：3686400–16777216。4.0：921600–16777216。宽高比都要在 1/16 到 16 | 与档位互斥 |
| 输出格式 | `output_format` | `png`、`jpeg`。5.5 默认 `png`，5.0 系列默认 `jpeg`。4.5 / 4.0 只有 JPEG，此项禁用 | 5.x 可选 |
| 透明通道 | `background` | `auto`、`transparent`、`opaque`。5.5 默认 `auto`，5.0 pro / flash 默认 `opaque` | 5.5、5.0 pro、5.0 flash。图层拆分时禁用 |
| 提示词优化 | `optimize_prompt_options.mode` | `standard`、`fast`，默认 `standard` | `fast` 仅 5.0 pro 和 4.0；其余模型只留标准并禁用快速 |
| 水印 | `watermark` | 开 / 关，官方默认开 | 全部 |
| 返回方式 | `response_format` | `url`、`b64_json`，默认 `url`。两种都会再存成本地文件 | 全部 |
| 组图 | `sequential_image_generation` | `disabled`、`auto`，默认 `disabled` | 5.0 lite、4.5、4.0 |
| 组图张数上限 | `sequential_image_generation_options.max_images` | 1–15，默认 15。参考图张数加生成张数不超过 15 | 仅组图打开时 |
| 流式返回 | `stream` | 开 / 关，默认关。打开后每出一张就先显示一张 | 5.0 lite、4.5、4.0 |
| 联网搜索 | `tools[].type = web_search` | 开 / 关 | 仅 5.0 lite |
| 图层拆分 | `layer_decomposition` | 开 / 关，默认关。打开后只允许一张输入图 | 5.5、5.0 pro、5.0 flash |
| 拆分张数上限 | `layer_decomposition_options.max_images` | 2–100，默认 30，含底图 | 仅 5.5，且拆分打开时 |
| 文字识别 | `layer_decomposition_options.text_recognition` | 开 / 关，默认关。只对规整文字图层返回样式 | 仅 5.5，且拆分打开时 |
| 终端用户标识 | `safety_identifier` | 可选，最长 64 个英文字符。留空则不传 | 5.5、5.0 pro、5.0 flash |

参考图在提交前于本地检查：格式为 jpeg、png、webp、bmp、tiff、gif、heic、heif；单张不超过 30MB；宽高比在 1/16 到 16；宽和高都大于 14 像素；总像素不超过 3600 万。图层拆分只接受 png、jpeg，总像素从 512×512 起。

透明通道和 JPEG 不能同时选。5.0 pro / flash 要出透明图时，参考图本身必须带透明通道，页面在提交前检查。5.5 的文生图也可以直接出透明图。

选「档位加比例」时，页面用方舟文档里的像素对照表提交 `宽x高`，保证 16:9 这类选择真正生效，而不是只写进提示词。对照表随模型升级维护；表里没有的组合改走自定义宽高。

### 7.4 页面上的视频参数

视频页对应 `POST /contents/generations/tasks`，完成后轮询并下载。任务类型决定素材槽，参数区始终是下面这一整组。

| 页面项 | 方舟字段 | 可选值与默认 | 哪些模型能用 |
| --- | --- | --- | --- |
| 模型 | `model` | 第 8 节列表；进阶可改填 Endpoint ID | 全部 |
| 任务类型 | `content` 的组合方式 | 文生视频；首帧；首尾帧；全模态参考；编辑；延长；样片转正式 | 按模型置灰。1.0 pro fast 没有首尾帧。1.0 没有全模态、编辑、延长 |
| 全模态意图 | `omni_reference_task_type` | `auto`、`reference`、`edit`、`extend`，默认 `auto` | 2.5、2.0 系列的全模态任务 |
| 提示词 | `content[].text` | 文本。编辑任务必须带一条参考视频，比例锁成 `adaptive`，时长锁成 `-1` | 全部 |
| 首帧 / 尾帧 | `image_url` + `role` | 首帧 1 张；首尾帧 2 张，角色分别为 `first_frame`、`last_frame` | 见任务类型。2.5 的首帧和首尾帧把比例锁成 `adaptive` |
| 参考图 | `role = reference_image` | 2.5 最多 30 张，2.5 flash 最多 10 张，2.0 系列最多 9 张 | 全模态，且不能和首帧模式混用 |
| 参考视频 | `role = reference_video` | 2.5 最多 10 条，2.5 flash 最多 5 条，2.0 系列最多 3 条 | 全模态。编辑、延长至少 1 条 |
| 参考音频 | `role = reference_audio` | 2.5 最多 10 段，2.5 flash 最多 5 段，2.0 系列最多 3 段。2.5 可以只传音频；2.0 不能只有音频 | 全模态 |
| 样片任务 | `draft_task.id` | 填一条仍在有效期内的样片任务 ID | 由样片转正式片时必填 |
| 分辨率 | `resolution` | `480p`、`720p`、`1080p`、`4k`。2.5 / 2.0 默认 `720p`；1.0 默认 `1080p`。2.5 flash、2.0 fast、2.0 mini 只有 `480p` 和 `720p`。1.0 没有 `4k` | 按模型切换。样片模式锁 `480p` |
| 宽高比 | `ratio` | `16:9`、`4:3`、`1:1`、`3:4`、`9:16`、`21:9`、`adaptive`。2.5 / 2.0 默认 `adaptive`；1.0 文生视频默认 `16:9` | 编辑、延长，以及 2.5 的首帧 / 首尾帧，只能 `adaptive` |
| 时长 | `duration` | 整数秒，或 `-1` 表示让模型选。2.5 为 4–30 秒，默认 `-1`；2.0 为 4–15 秒；1.0 为 2–12 秒。编辑任务只能 `-1` | 与帧数二选一 |
| 帧数 | `frames` | 29–289，且必须是 `25 + 4n`。用来出非整数秒。填写后优先于时长 | 仅 1.0 pro、1.0 pro fast |
| 生成声音 | `generate_audio` | 开 / 关，默认开 | 2.5、2.0 系列。1.0 禁用 |
| 水印 | `watermark` | 开 / 关，官方默认关 | 全部 |
| 封装格式 | `output_format` | `mp4`、`mov`，默认 `mp4`。选 `mov` 时提示播放器兼容性 | 仅 2.5 系列 |
| 随机种子 | `seed` | `-1` 到 2147483647，默认 `-1` | 仅 1.0 pro、1.0 pro fast |
| 固定镜头 | `camera_fixed` | 开 / 关，默认关 | 仅 1.0，且参考图场景禁用 |
| 返回尾帧 | `return_last_frame` | 开 / 关，默认关。打开后把尾帧 JPEG 一并存到本地，方便接下一段 | 文档未按模型拆开，先对全部视频模型提供；某模型报不支持时再禁用 |
| 样片模式 | `draft` | 开 / 关，默认关。打开后分辨率只能是 `480p` | 仅 Seedance 2.5 标准版 |
| 服务等级 | `service_tier` | `default`、`flex`，默认 `default`。`flex` 是离线推理，价格更低、时延更高 | 仅 1.0。2.5 / 2.0 禁用 |
| 排队优先级 | `priority` | 0–9，默认 0。只影响同一 Endpoint 里的排队顺序 | 2.5、2.0 系列。`flex` 下禁用 |
| 任务过期 | `execution_expires_after` | 3600–259200 秒，默认 172800（48 小时） | 全部 |
| 回调地址 | `callback_url` | 可选。留空则只在本机轮询 | 全部 |
| 联网搜索 | `tools[].type = web_search` | 开 / 关 | 2.5、2.0 系列 |
| 终端用户标识 | `safety_identifier` | 可选，最长 64 个英文字符。留空则不传 | 全部视频模型 |

视频用图在提交前检查：jpeg、png、webp、bmp、tiff、gif；2.0 及以上另接受 heic、heif。宽高比 0.4–2.5，边长 300–6000 像素，单张小于 30MB，整次请求体小于 64MB。大图只用本地文件转成请求，不在页面上鼓励贴超大 Base64。

分辨率选到 1080p 或 4K 时，若该模型会输出 10bit H.265，页面注明需要用 VLC、MPV 或 QuickTime 播放。个人账号的并发有限，页面默认同时只提交一条视频任务，队列里的下一条等上一条结束或失败后再发。

视频状态在结果区显示：排队中、生成中、成功、失败、超时、已过期。超时后保留任务 ID，可以继续查、继续下载，不重新扣一次费。

### 7.5 参数怎么提交

- 打开页面就能生成。没改过的项显示官方默认值，请求里不带这个字段。
- 用户改过的项，包括改成「关」，都显式提交。
- 点生成前，页面列出本次真实请求字段，Key 不出现在这份摘要里。
- 非法组合在点击前就拦住：JPEG 加透明通道、组图加图层拆分、首帧和全模态混用、样片却不是 480p、帧数不满足 `25 + 4n`、张数超过该模型上限。
- 换模型导致当前值失效时，该控件回到新模型的默认值，并在控件下留一句说明。

### 7.6 命令行与 Skill

命令行和 Skill 使用与页面相同的参数对象，用一份 JSON 表达，而不是只开放时长、比例这几个旗标。页面可以把当前配置导出成这份 JSON。

```bash
localtv config set-key
localtv config show
localtv run --params 参数.json
localtv job <id>
localtv job <id> --wait
```

Skill 只在用户明确要出图或出视频时调用。缺 Key 就停止。生成结束后交回本地路径；视频没完成时只报告状态。Agent 未写明的字段保持官方默认，不私自改水印、分辨率或时长。

## 8. 模型策略

模型目录做成配置，不把某个 Model ID 写死在业务流程里。方舟会更新版本号，也会下线旧模型。文档撰写时（2026-11-19）公开推荐如下，接入前再对着方舟模型列表核对一次。

### 8.1 图片：Seedream

默认模型：`doubao-seedream-5-5-261028`（Seedream 5.5）。它支持文生图、单图生图和多参考图生图，输出 PNG / JPEG。

| 模型 | Model ID | 第一期 |
| --- | --- | --- |
| Seedream 5.5 | `doubao-seedream-5-5-261028` | 默认 |
| Seedream 5.0 pro | `doubao-seedream-5-0-pro-260628` | 可选 |
| Seedream 5.0 flash | `doubao-seedream-5-0-flash-260915` | 可选，追求速度时 |
| Seedream 5.0 lite、4.5、4.0 | 方舟标记即将下线 | 仍出现在模型列表里，供组图、流式、联网搜索使用，并标注即将下线 |

图片接口：`POST /images/generations`。文生图只提交提示词；图生图额外提交参考图（URL 或 Base64）。

### 8.2 视频：Seedance

默认模型：`doubao-seedance-2-5-flash-261115`（Seedance 2.5 flash），用于日常试片。用户要求更高质量时改用 `doubao-seedance-2-5-260628`（Seedance 2.5）。

| 模型 | Model ID | 第一期文生视频 | 备注 |
| --- | --- | --- | --- |
| Seedance 2.5 | `doubao-seedance-2-5-260628` | 可选高质量 | 约 4–30 秒，最高到 4K；4K 并发更紧 |
| Seedance 2.5 flash | `doubao-seedance-2-5-flash-261115` | 默认 | 约 4–30 秒，480p / 720p |
| Seedance 2.0 / fast / mini | `doubao-seedance-2-0-260128` 等 | 可选 | 约 4–15 秒 |
| Seedance 1.0 pro / pro fast | `doubao-seedance-1-0-pro-250528`、`doubao-seedance-1-0-pro-fast-251015` | 可选，即将下线 | 种子、帧数、固定镜头和离线推理只在这一档 |

视频接口是异步的：

1. `POST /contents/generations/tasks` 创建任务，内容里放文本。
2. `GET /contents/generations/tasks/{id}` 轮询。
3. 状态为成功后，从返回的视频地址下载 MP4 或 MOV。

同一接口上的文生视频、首帧、首尾帧、全模态参考、编辑、延长和样片，都在创作页里按任务类型分开，避免互斥参数叠在同一次请求上。

### 8.3 选择规则

1. 出图用图片默认模型，出视频用视频默认模型。
2. `--model` 必须落在本地目录的允许列表中，避免把图片模型传给视频接口。
3. 用户要求的时长、比例、分辨率超出该模型能力时，停止并说明该模型的可选范围，不擅自改成另一个模型再调用。
4. 列表随着方舟文档更新，程序升级时可以刷新预设，已有项目记录仍保留当时实际使用的 Model ID。

## 9. 系统组成

从产品上看，LocalTV 是四块，都在本机：

```text
创作页 / 命令行 / Skill
        |
        v
  参数校验（按当前模型启用、禁用、互斥）
        |
        +--> 项目、任务与参数预设
        |
        +--> 方舟适配层 ----> 火山方舟 Seedream / Seedance
        |
        +--> 下载器 ----> outputs/
```

- **创作页**是人配参数的地方。控件和方舟字段一一对应，不在页面上合并掉官方参数。
- **参数校验**是页面、命令行和 Skill 的共同入口。不支持的值到不了方舟。
- **方舟适配层**是唯一知道 URL、鉴权头和字段名的地方。页面不拼 HTTP。
- **存储**负责任务状态。视频轮询中途进程退出后，下次仍能根据本地记录继续。
- **下载器**把方舟返回的临时地址尽快存到 `outputs/`。后续展示以本地文件为准。

## 10. 异常与边界

| 情况 | 产品行为 |
| --- | --- |
| 未配置 Key，或 Key 无效 | 停止生成，提示配置命令和方舟控制台入口 |
| 提示词或图片被审核拒绝 | 标记失败，展示平台返回的可公开原因，不自动改写提示词重试 |
| 参数不合法 | 调用前拦截；拦截不了的，展示方舟错误并指向冲突参数 |
| 参考图不存在、过大或格式不对 | 调用前拦截 |
| 限流或并发已满 | 标记失败或可重试，告诉用户稍后再查；不在后台无限重试造成重复扣费 |
| 视频生成超时 | 保留任务 ID，提示用 `localtv job <id> --wait` 继续 |
| 下载失败但任务已成功 | 保留远程任务 ID，允许只重试下载 |
| 网络中断 | 图片请求失败则任务失败；视频若已拿到任务 ID，则保持可继续查询 |
| 用户取消 | 本地标记取消。若方舟任务已创建且平台不支持取消，向用户说明云端任务可能仍会计费 |

日志可以记录模型、参数、耗时和错误码。日志不记录完整 API Key，不默认上传到任何 LocalTV 服务。提示词和图片会发送到火山方舟，这是生成所必需的，首次配置或帮助文案里写明。

## 11. 成功标准

1. 创作页上能看到第 7 节的每一个参数。换模型后，不支持的项禁用且不会被提交。
2. 只配置一次 Key，就能在页面上完成文生图、图生图和文生视频，并在本机拿到文件。
3. 改过的参数出现在请求摘要和任务记录里；没改过的参数保持该模型的官方默认。
4. 每个成功或失败的调用都有一条任务记录，视频记录能用来继续查询和下载。
5. Key 不出现在项目目录、页面摘要、命令回显和任务记录里。
6. 审核失败、鉴权失败、参数超限时，用户能看懂原因和下一步。

## 12. 里程碑

第一期内部按这个顺序交付，对外仍是同一个版本：三条能力一起可用才算第一期完成。

| 阶段 | 交付 | 完成的标志 |
| --- | --- | --- |
| M1 | 本机创作页、设置、图片参数全套、文生图和图生图 | 页面上能改第 7.3 节的每一项，并出图落盘 |
| M2 | 视频参数全套、异步任务 | 页面上能改第 7.4 节的每一项，视频可恢复下载 |
| M3 | 预设、请求摘要、命令行和 Skill 使用同一份参数 | 页面导出的 JSON 可以原样再跑一次 |

下一期只留本地剪辑和第二个供应商。组图、图层拆分、首尾帧和全模态参考已经算在这一期的参数页里。

## 13. 待确认

这些选择已经按上面的默认写进文档。若有不同决定，在开工前改掉即可。

1. **默认视频模型用 2.5 flash。** 页面上仍能选到 2.5 标准版和其余型号。若希望一打开就是最高画质，把默认改成 `doubao-seedance-2-5-260628`。
2. **即将下线的 4.x、5.0 lite 和 1.0 仍放在模型列表里。** 组图、流式、联网搜索、种子、帧数和离线推理只存在于这些模型。若希望列表里只留在售主力，这些参数会随模型一起从页面消失。
3. **图片水印的官方默认是开，视频水印的官方默认是关。** 页面照此显示，用户可以改。若希望图片也默认不带水印，把图片页的初始值改成关，并在请求里显式传 `watermark: false`。
4. **实现语言未定。** 创作页、参数校验和方舟适配选定一种实现后不再拆成两套。
